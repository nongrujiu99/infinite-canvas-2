# Pending Tests

- Pixels outside the painted area must not change: use an image with two copies of the same product (or a product plus another object on the table), paint only one of them and write “remove this”. Only the painted one should disappear; everything else must stay pixel-identical — same colour, lighting and texture, where this used to delete the other instance as well. The reverse also holds: an object the brush did not fully cover stays, because the painted area is the hard limit.

- Local edit adds no nodes: try all four entry points on an image node (right-click “Local edit”, the scan icon in the node header, dragging from the node's right port and picking “Local edit” in the create menu, and the toolbar's operations panel). Each should open the mask editor directly with zero new nodes, where it used to leave an operation card, a mask annotation node and a result node behind. The toolbar entry with nothing selected should say “Select an image first” instead of creating an empty card.

- Local edit overwrites in place with version history: paint an area, describe it, generate. The source image node itself should become the result, its size should follow the new image's ratio, and the node count should stay the same. The header should show “Versions 1”; opening it lists the previous image with its description and timestamp, and clicking restores it — after which the count becomes 2, because a restore is itself recorded. Version thumbnails must survive a page reload instead of turning into broken images.

- Removal stays inside the painted area: use an image that shows several identical products. Paint only the one in the hand and write “remove the bottle in the hand, keep the products on the table and beside it untouched”. Only that instance should disappear; the others must stay exactly where they were, and the hand or tabletop should be reconstructed rather than replaced with another similar product.

- A failed local edit must not destroy the image: cut the network or point the model at an unsupported channel and edit again. The original must still be there and the node must stay editable. If “Failed to load result” appears, the current image should be the new one and the previous version must be in the version list — never lose both.

- Legacy operation nodes merge themselves: an existing “Local edit” operation card from an older canvas should still run; after a successful generation the card disappears with a “Merged into the image node” message and the result lands on the image node.

- A single undecodable image no longer blanks the canvas: open the feature-preview canvas and every node and preview should render. Its previews are SVG data URLs, and a decode failure used to reject the whole `Promise.all` in `hydrateCanvasImages`, turning the canvas white.

- Prompt optimization (generation config node, image mode): the generation row should show an “Optimize” button with a strength dropdown. Light should keep the user's own wording and layout language and only fill in light, material and props; Full may re-compose. The result goes into a separate editable block below the input instead of replacing it, generation prefers that block, clearing it falls back to the original text, and editing the input marks the result as possibly stale. With only images connected it should read the product and describe its actual appearance; with a text node connected the `@[node:x]` reference must survive and still render as 文本N at generation time.
- Native GPT Image masking: painting an area in local edit and choosing GPT Image should send the original image plus a same-size transparent PNG `mask` field, with painted pixels transparent and untouched pixels opaque. Removal requests should delete the full target including parts, shadows, reflections, and residual outlines without reconstructing a replacement, while preserving the unmasked scene and reconstructing occluded hands or subjects where necessary. The canvas should not create a mask or result node: the result overwrites the source image in place and the previous image is kept under Versions. Non-GPT edit models keep the visual-reference fallback.
- Edited-image result sizing: successful local-edit, AI super-resolution, and multi-angle outputs should use the same maximum display edge and aspect-ratio-preserving sizing as ordinary generated image nodes, without changing the actual generated pixel dimensions.
- AI super-resolution limits: Nano Banana 2 / Pro should disable 4K and explain that the selected model supports up to 2K; GPT Image 2 and custom image scripts should retain 4K. A stale unsupported 4K selection must be blocked before any paid request, and a successful response below the selected resolution should be resized locally before storage so a 2K result has the exact requested pixel dimensions without another model call.
- Reference-image model compatibility: generation config, local mask editing, AI super resolution, and multi-angle dialogs should list only models compatible with the current `/images/edits` route; two-or-more-image requests should exclude single-reference models, and AI super resolution should expose only models with explicit target-resolution support. GPT Image edits should send only supported size/quality fields, Nano Banana edits should use URL response plus aspect-ratio/image-size fields, and other edit models should receive a minimal multipart body. An incompatible remembered or legacy-canvas model should switch to the first compatible option, or disable execution with a clear message when none exists, and the request service must reject stale incompatible selections before an API call is sent.
- Processing-result recovery: a failed local edit, AI super-resolution, or multi-angle result should show “Reconfigure”; selecting it should reopen the source operation dialog without sending or billing another request. Confirming AI super-resolution should reuse the failed result node and its existing connection instead of leaving a stale error node or creating a duplicate output, while ordinary generation failures should retain the explicit billed-regeneration label.
- Billed-result recovery: image generation, local edit, super resolution, multi-angle generation, image retry, and audio generation should retain an API result before local caching; caching failures should offer “Reload result” without another model call, resumable video failures should reuse the saved task ID, relative image URLs should resolve against the provider base URL, and ordinary image/text/audio/video failures should say “Generate again (may be billed)”.
- Multi-reference image editing: local mask editing and other edit requests with two or more reference images should send every file as a repeated `image` multipart field; local editing should retain the source aspect ratio while honoring the configured resolution (2K by default), and retrying older ratio-only results should normalize them to the current resolution instead of silently requesting 4K.
- Local-edit model filtering: the mask editor should list only image models known to accept reference-image editing (or custom image scripts), replace an unsupported remembered model with the first compatible option, keep favorites and recent results filtered, and disable AI generation when no compatible model exists while still allowing mask export.
- Connected empty outputs: when a generation-config node already has empty compatible output nodes connected, generation should fill them first and create only the missing image outputs needed for the selected count; connected nodes with existing content must not be overwritten, and video, audio, and text generation should likewise reuse only empty compatible targets.
- Image resolution enforcement: the resolution selector should hide unsupported 2K/4K choices for fixed-resolution Gemini-compatible models, explicit resolution should take precedence over quality for supported Gemini models, and a single warning should report requested versus actual pixels when a provider returns a different size during generation or retry.
- Nodeter canvas theme: light and dark canvas backgrounds, nodes, selection and focus states, toolbars, Ant Design overlays, connection flow, minimap, mentions, and mask editing should consistently use the logo-derived indigo and cyan roles with readable contrast and unchanged interactions.
- Text-node typography: text should retain the same Chinese sans-serif face, weight, size, and line height while editing and after leaving the editor, including empty and expanded batch text nodes.
- Brand logo: the website and documentation top navigation should show the complete Nodeter English wordmark, while the browser tab should show the indigo-and-cyan icon without theme recoloring or layout compression.
- Connected generation references: when a generation-config node has a normal prompt without explicit `@` tokens, every connected image, video, audio, and text input should still be included in the request; adding explicit `@` references should continue to select only the referenced inputs.
- Agent and plugin removal: the Canvas Library and existing projects should open without Agent connection flows, extension-node menus, plugin loading, or related local-storage entries. Built-in text, image, video, audio, generation-config, group, and processing nodes should retain creation, editing, connection, generation, undo/redo, and ZIP import/export behavior; custom model call scripts should continue working.
- Generation-config model picker: the model layer should open upward inside the node and follow canvas zoom without changing node dimensions or aspect ratio. Search, Recent, Favorites, All, scrolling, and empty states should remain usable.
- Generation-count default: a new generation configuration node should default to `1` in text, image, video, and audio modes without overwriting counts explicitly stored on existing nodes.
- Image-generation defaults: a new image-generation configuration node should default to 2K resolution and High quality while preserving the selected aspect ratio; explicit settings on existing nodes should remain unchanged.
- Documentation cleanup: the README and documentation site should describe only the current pages, built-in nodes, generation, assets, storage, and synchronization behavior. Business cooperation, sponsorship, QQ, contributor, Star History, remote showcase, and related navigation entries should be absent while Quick Start, the canvas guide, and both languages remain accessible.
- Local proxy transport: the development proxy should forward long-running text and video requests for up to 10 minutes without aborting, keep streaming SSE responses chunk by chunk, and return 504 with a clear timeout reason when the upstream times out.
- Strict structured text output: text requests that require a strict function call should use streaming Chat Completions with a strict tool schema, keep working on channels that only support Chat Completions, and fail fast with a readable message when the response is incomplete, returns the wrong function, or carries invalid arguments.
- General edit-model requests: image edits on models other than GPT Image and Nano Banana should explicitly request base64 output together with the configured format, size, and quality so the channel returns a parseable payload.
- Legacy detail-page nodes: opening an older project that still contains the removed detail-page operation nodes should drop those nodes and their connections instead of crashing the canvas.
- Video task retry: retrying a video node that still has a resumable task should resume the existing task instead of reopening the upstream processing configuration.
