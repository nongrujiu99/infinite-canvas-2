# Pending Tests

The current release needs manual verification in these areas:

- Image editor control consistency: crop ratio presets should render as equal-width 40px buttons with blue selected state instead of a dense black segmented strip; Reset, Cancel, and Confirm crop should share the same height and corner radius while keeping the primary action visually dominant. Split row/column inputs, line actions, and Generate children should use the same 40px / 12px control language, transparent secondary surfaces, consistent icon alignment, readable disabled state, and unchanged crop/split behavior at narrow and wide modal widths.
- AI multi-angle model selection: the dialog should show a current image-model picker, default to the last still-available image-edit model, and never inherit a retired model saved on the source image. Reset should preserve the selected model while restoring angle controls. The output ratio should follow the source image at the current configured resolution, and lens, model, reset, and Generate controls should share the compact 40px button language without changing angle, distance, connection, or error behavior. Clicking Retry on a failed multi-angle result should reopen the connected operation dialog so the unavailable model can be replaced instead of immediately repeating the same failed request.
- AI super resolution: configuring a Super resolution operation should show the source preview, require an explicit 1K / 2K / 4K target selection, preserve the closest supported aspect ratio of the source, and default to the last available image-edit model. Resolution buttons, model selection, output size, and the primary action should share the same compact 40px height, corner radius, theme-aware border, disabled treatment, and blue selected/primary language. Starting it should call the image-edit pipeline with a high-fidelity preservation prompt, create one independent downstream image node, show running/error state on both nodes, and never leave the previous Not implemented placeholder visible.
- Local mask editing model selection: the editor should show a searchable image-model picker above the edit instructions, default to the current image model, and submit the explicitly selected model without inheriting the source image's historical model. The result metadata and later retries should retain that selection, while ordinary text-to-image retries should continue retaining their saved model and parameters.
- Generation-config layout: image, video, audio, and text parameters should each stay on one horizontal row with fully readable labels and no overlap. Image mode should distribute ratio, resolution, pixels, count, quality, and transparent background across six equal columns; the pixel value should update when ratio or resolution changes, and image count should offer only 1–4 while existing larger canvas values generate at most four images. Select, Input, and InputNumber controls should use the same themed neutral surface instead of a pure-black background in both themes. Text mode should label its count as the number of candidate text options and keep all five reasoning-effort choices visible as compact buttons using the same border, blue selected state, hover, and keyboard-focus language as the generation-mode switch; selecting a button or generating multiple candidates must retain the existing behavior. Video mode should use five evenly distributed controls, no longer expose a watermark control, and always disable canvas video watermarking. Clicking the compact seconds value should open a slider whose range or discrete points match Sora, Veo, Grok, or Seedance model capabilities; switching models should immediately correct an unsupported saved duration, and unknown models should retain the 4–30 second fallback. The model picker must receive the remaining width beside a content-sized Generate/Stop button, including with long model names. Resizing the node should change only the available prompt-editor space. Double-clicking the prompt area should focus it, the expand icon should open a large synchronized editor, and long prompts or localized labels should scroll or reflow without being clipped. Existing model selection, references, `@` mentions, other parameter values, generation, and stopping behavior must remain unchanged.
- Image model ratio adaptation: ratio, resolution, and quality dropdown options inside a generation-config node should be clickable without starting node dragging, while dragging their surrounding empty space should still move the node. Switching among GPT Image, Gemini image, and Nano Banana models should immediately show only compatible ratios and replace an unsupported saved ratio with the nearest valid option. GPT Image generation/edit requests should keep using `size`; OpenAI-format Gemini/Nano Banana requests should use `aspect_ratio` and, on models that support it, `image_size`; Gemini-format requests should keep using `generationConfig.imageConfig`. Verify both text-to-image and connected-reference generation at 1:1, 16:9, and 9:16.
- Canvas connection feedback: dropping a connection on an empty upstream material node should show the specific upload-first warning instead of silently cancelling. Double-clicking any connection should remove it immediately without opening a menu. While a generation-config node is running, each valid outgoing result connection should show a restrained blue light segment moving from the config toward the output node, then disappear on success, failure, or cancellation; input, unrelated, and invalid connections must remain static, and reduced-motion mode should retain only a static state highlight.
- Empty material nodes and generation outputs: on empty Image, Video, and Audio nodes, only the central `+` control should open upload; dragging anywhere else on the node should move it. Holding Ctrl while dragging a node should create and move a copy with the original content preserved. An empty material node connected into a generation config must be rejected with an upload-first message, while an empty node connected from the config output must show Waiting for generation, replace the `+` with a non-interactive generation indicator, and disable uploading. Image-config output links must not exceed the configured image count; Generate should reuse already connected empty image nodes and automatically create and connect any missing result nodes, one generated image per target. Video, Audio, and Text generation should likewise reuse a compatible preconnected result node instead of adding a duplicate output connection.
- UI system upgrade: verify the Canvas Library, global navigation, project cards, canvas side panel, selected nodes, connections, generation configuration, floating toolbar, menus, inputs, disabled states, keyboard focus, and scrollbars in both light and dark themes. Blue should be reserved for active or primary states, secondary canvas controls should remain flat, and the 390px mobile Canvas Library should wrap its action controls without clipping while desktop retains the wide workspace hierarchy. Existing creation, selection, connection, generation, import/export, rename, delete, theme, and language behavior must remain unchanged.
- Canvas quick creation and text copying: right-clicking blank canvas space should open a compact menu for empty Text, Image, Video, Audio, and Generation config nodes and create the selected node at the clicked canvas position, without replacing node or connection context menus. Every text node should keep a subtle copy icon in its upper-right corner; clicking it should copy the current primary text, show the existing success message, and never start node dragging or text editing. Empty text nodes should show the icon disabled, and multi-text nodes should keep both the copy action and alternatives counter usable.
- Canvas typed workflow nodes: connections should flow from the always-visible, enlarged right output to the left input, reject resource-to-resource, operation-to-operation, duplicate, occupied, self, cyclic, and mode-incompatible links, and keep invalid targets from snapping while dragging. Text, image, video, and audio nodes should remain content-only; empty media nodes should offer a central click/drag upload entry, while populated media nodes keep always-visible name, dimensions/duration, size, and download information without a selected-node hover toolbar. Generation config should use a larger node that directly contains material references, drag ordering, `@` mentions, prompt editing, mode-filtered model selection, every generation parameter in a compact grid, and a small Generate/Stop button without secondary panels. Switching Image/Video/Audio/Text mode must preserve each mode's settings independently; incompatible existing links should remain as red dashed paused links, stay out of execution, recover when compatible again, and be manually removable. Populated image nodes should expose Crop, Split, Local edit, Upscale, Super resolution, Angle, and Reverse prompt from the right-click menu. The first six actions should create and connect their existing operation nodes before opening the unchanged processing flow; Reverse prompt should directly create its text and generation-config flow without an independent operation node. Blank-canvas double-click should do nothing, while image double-click should still open the large preview.
- Model and API configuration: the generation-config model picker should search compatible models by display name or Model ID, allow favorites, maintain removable/clearable recent usage, and never expose incompatible models for the active mode. Provider editing should show only API endpoint and API Key as its primary flow; Test and save should validate the endpoint, persist the provider, fetch all models, infer their capabilities, update the discovered counts, and make them immediately available to generation configs. Changing either credential should clear the connected status until it is validated again, and Fetch models again should repeat the same validation/sync flow.
- Canvas feature preview: the Canvas Library should expose a Feature preview action that creates a normal editable project using the real canvas runtime, with content-only text/image/video/audio nodes, a full-size generation-config node, a group, and sample typed connections. Opening it should enable the minimap and open the Agent panel. The guide and sample labels should describe the left/right ports, inline generation configuration, sortable connected assets, and standalone operation nodes. All regular canvas actions (move, zoom, box/multi-select, grouping, typed connections, left-side Canvas/Assets/Prompts tabs, import/export, plugins, undo/redo, appearance controls, and real AI generation after provider configuration) should remain available, and editing the preview must persist like any other canvas project.
- Canvas image previews: canvas image nodes, the left element list, the node reference bar, my-assets cards, the asset picker, image workbench result cards and history thumbnails, and the image/video workbench reference strips all render from a preview capped at a 768px long edge, so image-heavy views no longer decode the originals. Duration should stay compact until clicked, then open a model-aware slider with the current value visible; auto ratio should disable W/H.

## 图片分辨率尺寸表

选择分辨率和宽高比后，W/H 按下表填写，单位为像素。预设尺寸不受「16 倍数对齐」开关影响；该开关只控制手动输入尺寸时的对齐。最终生成尺寸以所选模型的实际输出为准。

| 宽高比 | 1K | 2K | 4K |
| --- | ---: | ---: | ---: |
| **1:1** | **1024 × 1024** | **2048 × 2048** | **2880 × 2880** |
| **2:3** | 1024 × 1536 | 1360 × 2048 | 2336 × 3520 |
| **3:2** | 1536 × 1024 | 2048 × 1360 | 3520 × 2336 |
| **4:3** | 1024 × 768 | 2048 × 1536 | 3312 × 2480 |
| **3:4** | 768 × 1024 | 1536 × 2048 | 2480 × 3312 |
| **16:9** | 1536 × 864 | 2048 × 1152 | **3840 × 2160** |
| **9:16** | 864 × 1536 | 1152 × 2048 | **2160 × 3840** |
| **21:9** | 2016 × 864 | 2688 × 1152 | **3840 × 1648** |
| **9:21** | 864 × 2016 | 1152 × 2688 | **1648 × 3840** |

待验收：

- 在画布和图像工作台逐项切换 3 档分辨率与 9 种比例，W/H 应与表格一致，重新打开设置后仍选中正确档位；重点检查 1K 的 2:3、16:9、21:9 及对应竖图，以及 4K 的 1:1。
- 所有 4K 预设提交时均不应触发本地总像素或最长边限制；生成和编辑请求、调用脚本应收到所选像素尺寸。
- 分辨率为自动时保留比例选择，比例为自动时禁用 W/H；手动输入 W/H 后，对齐开关仍应按原有方式工作。
- Gemini 在质量为自动时，应将表中尺寸识别为对应的 1K / 2K / 4K；显式选择质量时维持原有优先级。视频尺寸设置应保持原有行为。
