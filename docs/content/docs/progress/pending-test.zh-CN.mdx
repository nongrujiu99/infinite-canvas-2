# 待测试

- Photoshop 2020 主题（深色）：把主题切到深色，界面应是中性灰而不是发紫的蓝黑——工作区 `#1d1d1d`、面板 `#323232`、菜单与弹层 `#3c3c3c`，面板与工作区之间只差一档色加一根 1px 线，任何卡片都不应该有阴影。全屏唯一带颜色的是选中蓝：选中一行或一个芯片是整块 `#1a6ecc` 底加白字，焦点框是 2px 的亮蓝 `#2680eb`。若看到浅蓝底配蓝字、或选中项只有描边没有底色，说明样式被 antd 的无图层 reset 压住了。

- Photoshop 2020 主题（浅色）：切到浅色，应是「浅灰工作区 `#e2e2e2` + 近白面板 `#f4f4f4`」，不是之前的淡紫。顶栏是实心灰条、没有半透明模糊，选中页签是一整块浅灰方块、没有下划线。字标应是近黑色，不再是紫色加青色。

- 圆角只有两档：随便找一个按钮、输入框、下拉（3px）和一个卡片、侧栏、弹层（4px），用取景器看应都是近直角；8 / 10 / 12 / 14 / 16px 的圆角一个都不应出现。胶囊（状态点、徽标、主题切换圆点）仍然是圆的。

- 顶栏链接颜色：三个导航链接在深色下应是灰字（当前页是亮字），悬停变亮，不能是蓝字。实测对比度应 ≥ 4.5:1（改之前是 2.06:1，几乎看不清）。

- 提示词库分类整行高亮：`/prompts` 左侧「分类」是一列整行宽的列表，选中项（默认「全部」）应是一整条蓝底白字、宽度和侧栏内容区一致（约 199px），不是文字上浮着一个小药丸。悬停其他行应整行变浅灰。

- 画布配色：进入任意画布项目，工作区应是深灰 `#1d1d1d`，节点面板 `#323232`，网格点是中性白 10% 而不是靛蓝；框选矩形是蓝色描边加蓝色半透明填充，连线动画也是同一支蓝。切浅色主题后画布应是浅灰 `#e2e2e2`，网格点是中性黑。

- 对比度回归：深浅两套主题、三个页面（`/image` `/prompts` `/canvas`）跑一遍，文字对比度失败数应为 0；字号仍只有 22 / 14 / 12 三档。

- 字号只有三档：在 `/image`、`/prompts`、`/canvas` 任意一页打开检查器，逐个数文本节点的计算字号，应只出现 22（页面标题）、14（正文与控件）、12（说明与标签）三种，不应再看到 9 / 10 / 11 / 13 / 15 / 16。层级应靠字重（600 与 400）和颜色区分，例如区块标题与它的说明同为 14 / 12 号但一个是 `foreground` 一个是 `muted-foreground`。

- 圆角只有三档：同一页里统计所有可见元素的 `border-radius`，应只有 12px（按钮、输入框、标签、卡片内的行）、16px（大面板与弹层，如 `/prompts` 的卡片圆角、Modal）、胶囊（`rounded-full`，如状态点、徽标、开关）。嵌套在小圆角容器里的内层允许 8px，其余数值（1 / 2 / 3 / 14 / 18px）都不应出现——尤其是搜索框这类 large 控件，antd 默认会给 14px。

- 三页页头一致：`/canvas`「无限画布」、`/image`「生图工作台」、`/prompts`「提示词中心」三个标题的字号、字重、左边距应完全相同（实测均为 22px），标题下面各有一行 12px 灰字说明，右侧是那一页的操作（画布页是三个按钮，工作台是模型状态点）。`/prompts` 不应再有居中的大标题和背后的点阵图案。

- 画布页只保留一个「新建画布」：页头右上角有主按钮，空态区块里不再出现第二个同样的按钮；空态应只有图标、「还没有画布」与一行说明。页头三个按钮（导入画布 / 功能预览 / 新建画布）高度应一致，不再出现主按钮比其他两个高一头。

- 主色底上的文字：把主题切到深色，任意选中态的按钮（如区块折叠按钮的选中项、`/prompts` 侧栏选中的标签）文字应为深色 `#080b16`，与靛蓝底对比清晰；浅色主题下选中标签的文字应为白色。用取色器量一下，对比度应在 6:1 以上，若又变成 2.7:1 说明规则被 antd 的样式盖回去了。

- 键盘焦点环：不要用鼠标，直接用 Tab 键从头走一遍（必须真实按键，脚本里 `el.focus()` 不触发 `:focus-visible`）。每个可聚焦元素外圈应是 2px 实心靛蓝描边、离元素 2px，深浅两个主题都清晰可辨；不应出现 3px 淡紫（对比度只有 1.7:1，几乎看不见），也不应有元素完全没有焦点样式。

- 提示词库标签折叠：`/prompts` 左侧「标签」默认只显示 24 个，下方有一行「展开剩余 418 个标签」，点开后全部 440 个铺开、该行变成「收起标签」。先在收起状态下选一个排在第 25 位之后的标签（比如展开后挑一个冷门标签选中，再收起），它应收在列表里不消失——不能出现「选了却看不见自己选了什么」。窄屏（≤ 440px）下「展开」这一行也必须点得到，不能被侧栏的 `max-h` 裁进滚动区里。

- 工作台密度：`/image` 左侧控制栏在 1440×950 下需要滚动才能看到「05 视觉配方」和「补充描述」，这两块默认都是收起状态、各占一行；滚动时「生成电商图」按钮与参数摘要固定不动。生成按钮上的文字应是 14px（与旁边的参数摘要同级），不应比它大一号。

- 两个「管理」按钮应完全一致：02「平台与场景」与 05「视觉配方」标题右侧的「管理」，字号、图标大小、内边距、行高应逐像素相同（实测量得均为 26px 高、56px 宽、12px 图标），不再出现一个偏大偏亮的按钮；文案都写「管理」，悬停分别提示「管理场景」「管理视觉配方」。复制图标仍按内容有无决定是否出现——05 未选配方时不显示。

- 补充描述独立成块：它应出现在「05 视觉配方」下方、单独一行（不带序号），不再位于「02 平台与场景」内部；把 02 折叠起来后这一行仍然在。填一句话后展开，出图时点结果的「查看提示词」，末尾应有 `[Operator notes]` 段并包含这句话，且该段明确写着只作用于场景（`Apply it as scene staging only`）。换成视觉配方再生成，这句仍应出现。

- 区块可整块收起：02「平台与场景」与 05「视觉配方（可选）」的标题行（序号 + 标题 + 箭头）可点击，点一下整块内容消失、只剩标题这一行（约 48px），箭头朝下；再点一次原样展开，箭头朝上。刷新页面后收起状态应保持；点标题右侧的「管理」与「管理风格」不应触发折叠。01 产品图、03 参考图、04 生成设置三块不受影响，标题行点了没有反应。

- 配方不再吞掉平台纪律：选「亚马逊」+「纯净白底」配方，点开 02 区块的「实际下发的描述」，第一段应是 `[Platform look]` 并且包含 `Strictly neutral white balance` 与 `No beauty retouching`，末尾还应有「the recipe decides what is placed in the frame… Colour treatment and finish standard are never overridden」；第二段应是配方的纯白无缝底；**第三段「场景道具」应整段不存在**（配方自己安排场景，推导出来的道具没有位置关系）；第四段色调联动应仍在。出图时配方接管的是背景与承托面，平台的色彩与修图要求不能被配方带走。
- 产品锁要挡住「没装好」和「多出来」：拿一件带键帽或可动件的产品（客制化键盘、带旋钮的音箱）出图，`[Product lock]` 里应出现 `fully assembled and fully seated`、`keycaps sit flush down on their stems`、`hanging loop, strap lug, handle, hook, clasp`、`not already visible in 图片1` 这几句；成图里键帽不应悬空、轴座不应外露、机身侧边不应凭空多出挂环或提手。反过来，原图本身就是裸轴或透明外壳的产品，露轴是被允许的——这一句带了「原图没露才禁」的限定，不要当成 bug。
- 实际下发内容改为标题行复制：02「平台与场景」标题右侧应有一枚淡色复制图标，点击后图标短暂变成对勾，剪贴板里应是以 `[平台审美语言]`、`[场景与承托面]` 这类段名开头的英文原文（需在 https 或 localhost 下才允许写剪贴板）。05「视觉配方」在未选配方时没有这枚图标，选中任意配方后出现。02 与 05 底部不应再有「实际下发的描述」「配方下发的描述」这两行常驻入口。
- 平台决定光线：同一张产品图、同一个「桌面」场景，分别选「亚马逊」和「小红书」看提示词，`[Lighting]` 应完全不同——亚马逊只写均匀棚光、不出现任何窗口或自然光；小红书应以「The only light source is …」开头并声明不许用棚灯替换；天猫应是棚光在前、后面接「借这个方向但提亮柔化成可控棚光」。三段里都不应再出现同段内既「无阴影棚拍」又「左侧窗光扫过桌面」这种自相矛盾的组合。
- 平台决定道具：同一产品同一场景，依次切抖音、品牌 KV、亚马逊、小红书，`[Scene props]` 应分别是「几何色块平面 + 立方体」「符号化几何面 + 一片哑光织物」「整块不出现」「咖啡杯 / 杂志 / 绿植这类生活痕迹」。抖音桌面上不应再躺着笔记本和编织线；切平台时左侧摘要的「已补 N 件」和道具悬浮列表要跟着变。关掉属性联动后各平台最多剩 1 件（亚马逊为 0）。
- 场景光源只写空间事实：场景管理里编辑任意内置场景，「可用光源」填的应是「有什么光、在哪」（如「桌左侧有窗」），而不是软硬与色温；从场景图识别新建时，识别结果里的光源也应只给来源与方向，不再给光质和色温。
- 背景由平台决定：同一张产品图、同一个「桌面」场景，切亚马逊看提示词，`[Scene]` 里应完全不出现显示器、线缆这类东西，背景读作「一面失焦的哑光墙 + 一整片向边缘柔和衰减的色」；切小红书应保留「the lower edge of a monitor」；切天猫、独立站应保留墙面材质但同时写明「and nothing else in it」。出图对比时，亚马逊与品牌 KV 的产品背后不应再有任何可辨认的器具、电器或线缆。
- 承托面材质与修饰不能打架：给一件亮面塑料产品（如客制化小键盘）选桌面场景，承托面应写成「smooth acrylic desktop with a plainly visible front edge」，不应再出现 open grain / veining / speckle 这类跟材质绑定的词；换成金属或木质产品时材质与修饰要同步换，不能拼出「哑光层板 + 木纹」这种组合。场景编辑器「环境与光」里新增的「交代地点的器具」一栏，留空后任何平台都不应再出现该器具。
- 提示词优化（生成配置节点 · 图片模式）：输入框下方的生成栏应出现「优化提示词」按钮与强度下拉。轻档应保留输入的原话与版式语言、只补光影材质等细节；中档允许重组版式。结果写入输入框下方的优化区，原有输入不被覆盖；清空优化区后生图回退到原文；改动输入后优化区提示「结果可能过期」。仅连接图片时应读到产品并按其外观描述；连了文本节点时应以 `@[node:x]` 保留引用，生图时仍渲染为「文本N」。
- 生图工作台入口：顶部导航应出现「生图工作台」，进入 `/image` 后四个步骤区块（产品图、场景风格、参考图、生成设置）与右侧结果区完整渲染，切回「我的画布」和「提示词库」不受影响，`/` 仍直接跳转画布。
- 产品识别：上传白底产品图后应自动识别出品类、子类、材质、表面处理、主色与机位，并显示机位判断；主色应取机身色而非背景色。手动改品类后重新识别，品类应保持用户选择。
- 主色兜底：在**没有配置渠道**的情况下上传一张白底浅色产品图（如浅杏粉外壳），识别应照常失败并提示手动选品类，但产品图下方仍应出现一个色块与形如 `#CFAFA1` 的色号——它是本地采样算出来的，不依赖网络。把鼠标悬停上去，提示应说明是本地兜底。随后手动选一个品类，色号必须还在（不能被选品类冲掉）。换一张产品图后色号应立即变成新图的值，不能留着上一件的。
- 颜色锚点：上传上述浅杏粉产品后查看提示词，`[Color]` 里除色号外应多出一句 `The body colour is a warm blush — …` 并点名 `not a lilac, not a lavender, not a mauve`。换成一件浅紫产品（如 `#B9A7E0`）再生成，这句应变成 `a pale lavender` 且反过来把 `a warm blush` 列为错误答案。删掉产品图或用一张完全取不到主色的图时，这句应整段消失，`[Color]` 除色号外与旧版一致。
- 色调锁措辞：任意产品、任意场景，左侧「属性联动」的依据里那条应显示为「产品色相 → 锁住」，不再显示「暖色产品 → 锁住色相」（后者会让人以为真的识别出了暖色，而它对所有明度都生效）。提示词 `[Color]` 末尾应出现「环境只许改光量与反光强度、色相一个方向都不许动」这段，不再是旧的「暖产品别加暖光」。
- 识别降级：未配置 Base URL 或 API Key 时上传图片不应发起请求，只提示配置；换成不支持图片输入的中转模型，识别应失败并提示手动选品类，随后生成仍可用。
- 参考图拆解：上传参考图后切换五种模式，每次切换应重新拆解并清空旧结果；「构图版式」应额外给出机位。风格卡片上应实时显示被覆盖的字段；某张拆解失败时该张不参与合并，其余参考图与预制风格照常生效。
- 保真效果：同一张产品图分别用「干净」与「科技感」两组风格生成，产品轮廓、按键数量与位置、接口、logo 位置、机身颜色与哑光质感应保持一致，仅背景与光线随风格变化；不应出现镜像产品、重复产品、多余按键或非原设计的灯效。
- 机位策略：默认应保持原图视角；切到「换个角度」后候选按风险从低到高排列，选中的机位写入提示词。对俯拍平铺的图，候选应全部标为高风险并提示重拍。
- 生成参数隔离：在工作台把比例改成 16:9、数量改成 3 并生成，然后切回任意画布节点，确认该节点的尺寸、数量与模型未被改动。
- 结果处理：生成结果应可预览、查看当次提示词、下载、存入「我的资产」、单张删除与清空；存入资产后资产页应能看到图片与提示词元数据。
- 风格管理：编辑内置风格后应出现「已修改」标记并可一键恢复默认；停用某风格后它应从工作台列表消失；新建与复制风格刷新页面后仍在；实时 prompt 预览应随字段编辑同步变化。
- 尺寸兼容：换成 GPT Image 系列并选择 2K / 3:4，请求尺寸应自动收敛到该模型支持的档位，不因尺寸不支持而报错。
- 端点自适应：选中中转站里只声明了 `chat/completions` 或 Gemini `generateContent` 的图像模型（如 `gemini-nano-banana`）生成时，不应再报「当前模型不支持本次 API 端点」；应自动落到能用的端点，生成栏摘要末尾显示「走 xxx」，第二次生成不再先打一次必然失败的请求。换回 `gpt-image` 系列应仍走 `/images/edits`。
- 工作台两栏布局：桌面端编辑区应只占左侧约 320–340px 窄栏，生成按钮与参数摘要固定在控制栏底部、结果区独占右栏；控制栏自身可滚动且不带动整页滚动，结果区列数随窗口变宽增加（1080 宽 4 列、1440 宽 5 列），窗口缩到 1024 以下恢复单列整页滚动。
- 补充描述：在「场景风格」底部默认只显示一行「＋ 补充描述 · 加道具、桌面材质、氛围」，点开后出现输入框。选「桌面极简」并填写「桌面上另放一台手机、一台平板和电子阅读器作点缀」，生成栏摘要应出现「含补充描述 · 原文」，结果的「查看提示词」里应多出 `[Operator notes]` 区块、位置在 `[Scene]`/`[Support]` 之后、`[Lighting]` 之前，且道具没有盖住产品、没有顶替产品。
- 补充描述不串味：清空输入后生成的提示词应与添加该功能前逐字一致（不再出现 `[Operator notes]`）；填写「把产品改成红色」这类句子时应出现「更像在改产品本体」的提示，但输入不被拦截，生成时产品颜色仍以产品图为准。
- 补充描述的长度与换行：粘贴多行中文应压成一段且中文之间不插空格；超过 400 字应被截断，计数器在接近上限时变色。
- 补充描述与参考图共存：上传一张「风格迁移」参考图并等拆解完成，风格区块同时出现「参考图覆盖了这套风格的：场景、光线、构图、配色」与补充描述输入框，生成栏摘要仍显示「含补充描述」。查看提示词时 `[Scene]` 应为「风格场景 + 参考图场景」拼接，`[Operator notes]` 在其后，且写明道具以手写为准、其余仍听参考图。
- 补充描述与整条禁道具的冲突：选「纯净白底」（该风格禁区里整条写着 `props`）并填写要加道具的补充，`[Avoid]` 行尾应多出「the props named in [Operator notes] are allowed and expected」；清空补充后这一句必须消失，`[Avoid]` 与原来逐字一致。选「桌面极简」这类本就允许道具的风格则不应出现这句。
- 风格管理预览范围：风格编辑里的「实时预览」只展示风格本身贡献的提示词，标注「仅风格部分」，不应混入本次的补充描述与参考图。
- 从风格图新建：风格管理 → 新建风格，顶部出现「从风格图识别」卡片；传一张环境明显、产品占比小的图，识别完成后应直接多出一个自建风格（列表里排在最后、带缩略封面），编辑器停在它上面且字段可改。用该风格在工作台生成时，画面场景/光线/配色应与参考图一致，且不要把参考图里的产品特征带进来。
- 从风格图新建的缺省与失败：把图里的产品占满画面、或光线很平的图传进去，识别结果里「承托物」应为空（生成时不会凭空多一块台子）；未配置识别渠道时点上传应给出「还没有可用的识别模型」提示而不是无反应；模型返回非 JSON 时应出现可重试的报错，且不会产生半套风格。
- 参考图拆解存为风格：工作台上传一张「风格迁移」参考图并等拆解完成，参考图区块标题右侧出现「存为风格」；点击后风格列表多出「参考图风格」（重名自动编号），场景/光线/构图/配色/禁区与拆解结果一致、承托物为空，封面取该参考图；移除参考图后仅用这套风格生成，画面观感应保持一致。
- 存为风格后的卡片与选中：点「存为风格」后新风格应立刻被选中（卡片出现高亮描边与勾选），且卡片顶部显示那张参考图的缩略图、配色压成底部细线，一眼能和左右两排纯色条的内置风格区分开；同一流程在风格管理左侧列表里也应显示缩略图。
- 中转站「价差 / 供应」报错的提示：用带参考图的配置生成并触发「所选供应的价格超出当前价差范围」时，生成栏红色报错下方应多出一行小字，说明这是令牌价差拦下的供应、并给出「先移除参考图再生成一次」的验证动作；不带参考图时该行改为提示换 1K 分辨率或换模型。
- Agent 与插件移除：画布项目库及已有画布应可直接打开，不再出现 Agent 连接流程、扩展节点菜单、插件加载或相关本地存储项；内置文本、图片、视频、音频、生成配置、分组和处理节点的创建、编辑、连线、生成、撤销重做、ZIP 导入导出逻辑保持不变，自定义模型调用脚本继续正常工作。
- 生成配置模型选择：模型选择层应在节点内向上覆盖显示并跟随画布缩放，不改变节点尺寸或比例；搜索、最近使用、收藏、全部筛选、滚动和空状态应保持完整可用。
- 生成数量默认值：新建生成配置节点在文本、图片、视频和音频模式下的生成数量均应默认为 `1`，已有节点明确保存的数量不应被覆盖。
- 文档清理：README 和文档站只描述当前存在的页面、内置节点、生成、素材、存储与同步能力；商务合作、赞助、QQ群、贡献者榜单、Star History、远程展示图和相关导航入口不再出现，快速开始、画布手册及中英文导航仍可正常访问。
- Docker 镜像推送：在最新提交上手动触发「Docker image」与「Docs Docker image」两条工作流，构建应成功并推到 `ghcr.io/nongrujiu99/infinite-canvas` 与 `ghcr.io/nongrujiu99/infinite-canvas-docs`；仓库 Packages 里能看到带 `latest` 与版本号标签的包，`docker compose pull` 能直接拉到而不再 404。
- 工作台控制栏两列：桌面端控制栏宽度约 544–576px，产品图 + 场景风格在左列、参考图 + 生成设置在右列，两列之间的竖线贯穿到面板底部、生成条横跨两列；风格卡为两列排列且名字完整显示。窗口缩到 1024 以下恢复单列整页滚动，640–1024 之间仍是两列但占满宽度，640 以下按「产品图 → 场景风格 → 参考图 → 生成设置」顺序堆叠。
- 上传区尺寸：产品图与参考图的上传框高度一致（约 104px），两列并排时标题、上传框底边、下一块区块标题水平对齐；拖拽悬停时整块高亮，落点范围随之变大。模型选择独占一行并完整显示模型名，「高级」移到标签行右侧。
- 生成记录持久化：在工作台生成 1–2 张图后刷新页面，结果应原样还在（图片正常显示、风格名与「查看提示词」可用），而不是空态；再刷新一次仍在。删掉产品图后结果仍需保留，可继续查看提示词、存素材、下载。「清空」按钮才是唯一清空入口。
- 偏好不再被刷新覆盖：把比例改成 16:9、分辨率 1K、模型换成别的，刷新后这些选择应保留（此前会被初始默认值覆盖）。
- 比例与分辨率：比例下拉应有 9 项（1:1、2:3、3:2、4:3、3:4、16:9、9:16、21:9、9:21），模型只支持固定比例时（如 nano-banana 一类）自动过滤掉不兼容项；分辨率下拉显示「1K · 1024 × 1024」「2K · 2048 × 2048」这样的真实像素，切到 3:4 后应变成「2K · 1536 × 2048」，生成结果与摘要里的比例、尺寸一致。
- 多产品图组图保留：传一张摆了 3–5 件产品的主图（如三件套 / 一排不同颜色同款），识别后产品图区块应出现「N 件」小标签且 N 与图上实际件数一致；生成结果里这 N 件都要在，颜色、相对大小与摆放关系与上传图一致，不能只出其中一件，也不能凭空多出图上没有的那一件。
- 多产品图不串成道具：多件图生成时，背景道具不应挤占或遮挡其中任何一件，被裁掉边缘的情况也不该出现；「查看提示词」里 `[Product lock]` 应为「holds N separate product units」，`[Avoid]` 里不应再出现 `duplicated product`，而是「missing product unit / extra product unit」。
- 单件产品回归：传一张常规单件主图，识别结果不应出现「N 件」标签，`[Product lock]` 仍为「one unique product instance」，整份提示词与本次改动前逐字一致。
- 画布贴产品：上传一张带白边的主图（四周留白可以不对称），框的边框应正好贴住产品本体，不是贴住整张图的外边；框内看到的应该只有产品，没有白边。按住框拖动应立即变成实线、框内左上角显示百分比、右上角出现「恢复自动」；拖右下角小方块应等比放大缩小，% 数字跟着变。切到 16:9 时框会自动收窄到放得下（约 52%），不会有一半露在画外。点「恢复自动」应回到虚线占位、宽度回 60%、按钮消失。点「小 / 中 / 大」四档应落在同一个框上，16:9 下点「大」受高度上限约束约为 52%。生成栏摘要末尾出现「占比 52%」这类百分比。「查看提示词」里 `[Framing]` 应写成「spans about X% of the frame width, with its centre Y% in from the left edge and Z% down from the top edge」，并带上「upper right / lower left」这类方位词。保持默认（自动、没拖过）时「查看提示词」里不应出现 `[Framing]`，与改动前逐字一致。
- 构图实际效果：同一张产品图，把框拖到左上并放大、再拖到右下并缩小，分别生成一次：前者产品应在左上、留白集中在右下且整体偏大，后者相反；两次都不应出现产品被裁切、拉伸或压扁。
- 构图与多件图共存：多件产品图把框拖到画面一角时，`[Framing]` 里的主语应为「the whole group」，整组作为一个包围盒被缩放与定位，不应只挪动其中一件。

- 位置真的生效（硬控）：把框拖到画面左下、缩到约 40%，生成一次。结果里产品的中心应落在左下区域、占宽接近 40%，不再是「居中放大」。判据是产品中心与框中心相对画面的位置一致（肉眼对齐即可，允许一点点偏差），且产品没有被裁切、拉伸。生成时按钮转圈会比以前多一点点，因为要先合成一次。
- 白底被填满：构图合成会把产品放在白底画布上，成片里产品四周应该是正常的场景（桌面、背景、光影），不应该残留白边、灰边或一块空白。
- 自动模式不受影响：把构图点回「恢复自动」再生成，请求里提交的仍是原始产品图（可在浏览器开发者工具的请求体里确认图片大小与上传时一致），成片与这次改动前一样。

- Gemini 系模型能出图：生成设置里选一个 `gemini-nano-banana` / `gemini-*-image` 这类模型，正常生成一次。此前会报「当前模型不支持 OpenAI 聊天调用，请按模型页面说明使用 Gemini 原生出图接口」，现在应直接出图（中转站支持的话）。若中转站既不支持 `/images/edits` 也不支持 `/v1beta/models/...:generateContent`，错误提示里会列出试过的每个端点及各自原因，而不是只丢一句。
- 模型切换自由：点「模型」下拉能列出**所有渠道**里能力为「图片」的模型（选项右侧带渠道名），选中后立即生效、刷新后保持。若某个想用的模型不在列表里，说明它被按名字猜成了别的能力（文本 / 视频 / 音频），需要到渠道配置里重新拉取或调整。
- 非 Gemini 模型的端点自适应：选中 `gpt-image` / `flux` / `seedream` 这类模型，在**只实现了 `/images/generations` 或只实现 `/chat/completions`** 的中转站上生成（即 `/images/edits` 返回 404 `Invalid URL` 或 `Not Found`），应自动换到能用的端点并出图，而不是直接抛 `Invalid URL (POST /v1/images/edits)`。有参考图时不应退到纯文生图端点（否则产品图会丢）。
- 参数错不再乱试：把分辨率选成该模型不支持的值（或让 prompt 超长）后生成，应在**第一次请求后**就把上游原文（如 `Invalid value: 'size'...`）显示出来，而不是连打 3 个端点再报一句「该模型不支持任何出图端点」。同理，模型名写错（`model_not_found`）、Key 无效（401）、余额不足（402）、限流（429）都只请求一次。
- 国产模型的参考图不再被本地拦掉：选 `doubao-seedream` / `kolors` / `hunyuan-image` 这类模型并上传产品图生成，不应再出现「当前渠道没有支持此参考图操作的模型，请配置兼容模型或自定义调用脚本」。若该模型的图生图挂在 `/images/generations` 上，应自动落到那条端点并把参考图一起提交（生成栏摘要末尾显示「走 /images/generations」）。**判据是：结果里的产品与上传的产品一致**——如果出图是纯文字生成的另一个杯子，说明参考图没被接受。
- 本地能力名单只影响界面：在画布节点里用 `doubao-seedream` 加参考图，模型列表与「同时提交参考图」开关应可用；若模型实际不支持，报错应来自服务端原文，而不是本地那句「没有兼容模型」。

## 平台 × 场景（三层场景系统）

- 左栏「02 平台与场景」能看到 6 个平台（天猫电商 / 亚马逊 / 小红书 / 抖音电商 / 品牌 KV / 独立站）和 13 个场景（桌面 / 窗边 / 床头 / 厨房 / 浴室 / 玄关 / 客厅 / 户外 / 咖啡馆 / 车内 / 健身房 / 影棚 / 参考图场景）。切换平台时比例会自动跟着建议值走（选小红书应变 3:4，分辨率同步变成 768 × 1024 这类竖版），场景切换不改编。
- 同一场景换平台应当明显不同：都选「桌面」，天猫应是亮净的商业修图，小红书应是窗光随手拍并允许手入镜，亚马逊应是中性写实几乎无造型。如果两种平台出图几乎一样，说明 `[Platform look]` 没进提示词，可在结果详情里翻 prompt 确认。
- 属性联动生效：上传一张**深色金属**产品（如深灰铝合金）并等识别完成后，选「桌面」场景，「依据」一行应出现「深色金属 → 深色木面」，成片承托面是深色木面而不是默认浅木。换一张**浅色硅胶**产品，承托面回到场景默认，依据里变成「硅胶 / 类肤 → 哑光环境」。
- 承托物不该被材质规则改名：选「客厅」（茶几）配一件深色金属产品，提示词的 `[Scene]` 里应仍是「coffee table」而不是「desktop」；选「窗边」应是「windowsill」。出现「客厅里的桌面」就是这条回归了。
- 不会与产品同类：上传一副耳机（品类识别为音频），场景道具里**不应**再出现另一副耳机。此前版本会摆一对耳机，模型容易画错主体。
- 户外/车内不出现室内陈设：「户外」场景的道具里不应有唱片封套、便签、鼠标这类东西；「车内」只应有充电线、墨镜一类。
- 影棚必须干净：场景选「影棚」，无论什么平台、什么材质，「依据」应显示「影棚 → 只留产品」，提示词里**没有** `[Scene props]` 段，承托面是无缝背景纸（不会变成深色木桌面）。配合「亚马逊」就是可以直接过审的白底主图。
- 关掉属性联动：把「属性联动」开关关掉后，提示里应变成「已关闭联动，只保留 N 件交代地点的道具」，成片只剩场景本身的东西。
- 参考图场景：场景选「参考图场景」但没上传参考图时，应提示「还没有可用的场景参考图，本次暂用影棚场景」并真的按影棚出图；上传一张环境参考图并把模式设为「场景」后，`[Scene]` 应改为参考图拆解出的环境。
- 视觉配方仍可用：「05 视觉配方（可选）」里点任意一套（如「纯净白底」），左栏顶部会出现黄色提示「正在用自定义配方…平台与场景不生效」，此时提示词里**不含** `[Platform look]` / `[Scene props]`，画面回到旧行为；点「改用平台场景」可退回。
- 老存档平滑升级：升级后第一次打开，之前选过的风格配方会被清空一次，界面落在「天猫电商 · 桌面」。自建风格仍在「管理风格」里，没有丢失。

- 场景可以自己加：打开「02 平台与场景」右上角「管理」→ 场景页签 → 「新建场景」，改完名称、承托面（材质 / 承托物）、背景、光源、道具后保存，工作台场景列表里应立即出现并带「自建」角标；选中它生成，摘要与提示词里应是新场景而不是回退成桌面。
- 自建场景继承规则：把自建场景的「行为归类」选成「影棚」，生成时不应出现任何道具；选成「户外」，不应出现唱片封套、便签这类室内陈设。
- 识别建场景：在「新建场景」里点「选择一张场景照片」，传一张环境完整、产品占比小的图，应自动填好承托面、背景、光源、行为归类和道具，并提示已保存为自建场景；识别失败时应明确报错且仍可手动填写，不应存出空壳场景。
- 内置场景可改可恢复：改一个内置场景的承托物名词后保存，工作台立即生效；点「恢复默认」应回到出厂描述，已生成的历史记录不受影响。停用某场景后它不应再出现在工作台的场景列表里。
