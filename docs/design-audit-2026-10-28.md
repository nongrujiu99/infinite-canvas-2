## 二、反模式判定（先说这个）

**结论：部分页面会立刻被认成 AI 生成，另一些不会。这正是问题——产品自己不一致。**

- **`/canvas` 是教科书级空状态模板**：920×330 圆角大卡 + 圆形图标 + 居中标题 + 居中副标题 + 居中主按钮，五个元素全部居中堆叠。这个组合在 2024–2025 的生成式产品里出现频率过高。
- **`/prompts` 是等高卡片网格模板**：居中大标题 + 巨型搜索框 + 左侧 20 多个标签链接 + 4 列卡片（图 16:9 / 标题 / 描述 / 标签 / 两枚按钮），同一模板重复 20 次。标题区背后还铺了一层点阵渐变。
- **`/image` 反而不像模板**：580px 密集工具面板 + 右侧工作区，信息密度和分组逻辑都是真实业务长出来的。它是三者里唯一有"产品感"的页面。
- **最饱和的像素给了次要功能**：`05 视觉配方` 的 10 张渐变卡（桃 / 青 / 橙 / 蓝 / 米 / 灰）是全屏色彩最重的东西，而主路径（平台 / 场景）全是 10–11px 灰字。层次倒置。
- **等宽字体当技术感**：区块序号 `font-mono text-[10px] tracking-[0.14em]`（`section.tsx:47`），序号本身没问题，但那 0.14em 字距纯属装饰。

## 三、排版（这是最严重的一块）

### 3.1 首屏 71% 的文字小于 12px

`/image` 首屏 96 个文本节点实测分布：

| 字号 | 数量 | 占比 |
|------|------|------|
| 11px | 40 | 42% |
| 10px | 26 | 27% |
| 14px | 19 | 20% |
| 13px | 5 | 5% |
| 12px | 2 | 2% |
| 9px | 2 | 2% |
| 15px / 16px | 1 / 1 | 2% |

**68 个（71%）在 12px 以下。** 正文（"上传产品图，选一套场景风格…"、"亮、净、贵。高调商业修图…"）全部是 10–11px。

后果不是"小一点不好看"，而是：
- 产品里所有**结构性信息**（平台名、场景名、区块序号、说明）和**次要信息**（提示、备注）处在同一字号，靠 1px 差和灰度区分，等于没有层次；
- 中文在 10px 下笔画糊在一起，长时间用会累；
- 这是 DPR 1 的显示器才勉强能看，高分屏缩放 125% 后更难。

### 3.2 八档字号挤在 7px 区间内

`9 / 10 / 11 / 12 / 13 / 14 / 15 / 16`。相邻档差 1px，比例约 1.09。

设计系统文档（`DESIGN.md`）declares 的是四档：Display 48 / Title 20 / Body 14 / Label 12。**代码里一档都没按这个来。**

### 3.3 页面标题三套，且都不是文档里那套

| 页面 | H1 | 字号 | 字重 | 对齐 |
|------|----|------|------|------|
| `/canvas` | 无限画布 | **48px** | 500 | 左 |
| `/prompts` | 提示词中心 | **24px** | 500 | 居中 |
| `/image` | 生图工作台 | **15px** | 500 | 左 |

48、24、15——差 3.2 倍。`DESIGN.md` 说 Display 3rem 只给"项目级页面标题"，那么 `/prompts` 和 `/image` 都在违规，但违规方式不同。用户从"我的画布"点到"生图工作台"，感觉像换了产品。

`/image` 的 H1 是 15px，比它自己的二级标题（13px）只大 2px，比正文（11px）大 4px。**页面标题在图里根本不成立。**

### 3.4 字号靠手写逃逸，系统档位形同虚设

```
text-[10px] / text-[11px] / text-[9px]  → 155 处，分布在 28 个文件
text-xs (12px)                          → 140 处
text-sm (14px)                          → 112 处
```

手写小字号比 `text-xs` 还多。最密集的是 `scene-editor.tsx`(13)、`look-picker.tsx`(13)、`studio-settings.tsx`(12)、`style-editor.tsx`(11)、`canvas-node.tsx`(11)。

这说明团队在设计时是"这一处想小一点"就写一个任意值，而不是"这是哪一档"。**没有档位，就没有层级，只有一堆差不多大的灰字。**

## 四、颜色与对比度

### 4.1 [P1] 选中态 2.72:1 —— 全站唯一真正不达标的地方

实测两处（`/image` 角度分段控件「保持原角度」「自动」）：

```
前景 rgb(242,244,255)  背景 rgb(129,140,248)  对比度 2.72 : 1   （要求 4.5）
```

根因不是配色，是**工具类没生效**：

- `studio-settings.tsx:224` 写的是 `bg-primary text-primary-foreground`；
- 但实测该元素 `color` 仍是 `rgb(242,244,255)`（= `--foreground`），**不是** `--primary-foreground`（#080b16）；
- 同一页面里 antd 的 `type="primary"` 按钮走 CSS 变量，能得到 #080b16 → 6.55:1，正常。

所以同一个产品里，**两种主按钮的文字色不一样**，一种合格一种不合格。这是本次审计里唯一一处"用户会真的看不清"的对比度问题，但也正因为只有它，修起来最划算。

### 4.2 [P1] 导航焦点环 1.74:1

真实键盘 Tab 实测，顶部三个导航链接的焦点环是：

```
outline: solid 3px rgb(53,56,88)   落在 rgb(8,11,22) 上 → 1.74 : 1  （要求 3:1）
```

几乎不可见。而 `globals.css:152` 明明有 `:focus-visible { outline: 2px solid var(--ring) }`，`--ring` 在深色下是 #818cf8（对比度 6.2:1，够用）——说明这条规则没有覆盖到导航链接，它们落回了浏览器默认环。

同一页面里其余按钮的焦点环是 `2px rgb(129,140,248)`，看得见。**所以焦点可见性不是全局坏掉，是一处漏接。**

### 4.3 [P2] 暖色横幅破坏了冷色体系

两处 `bg-amber-500/10` + `text-amber-700/400`（未配置渠道提示、正在用自定义配方提示）。实测底色 `oklab(0.769 0.064 0.177 / 0.08)`——在冷靛蓝画布上是一块暖米色。

`DESIGN.md` 的 Don't 第一条就是："**Don't** mix warm beige surfaces into the cool neutral working palette."

这两条提示在语义上确实需要"注意"，但用暖色换注意力，代价是整个调色板的温度被拉偏。冷色体系里表达"注意"应该用靛蓝加深 + 图标，而不是借暖色。

### 4.4 做得好的部分

- **灰色三层真的立住了**：正文 `#f2f4ff` 于 `#111528` = 7.5:1，次要 `#a3a9c2` = 5.4:1，边框 `rgba(165,180,252,0.16)` 克制。深色模式整体不刺眼。
- **全站只有 2 个对比度失败点**，而且都是同一个组件。这个成绩在深色主题产品里算好的。
- **青色没有被拿来装饰**，只出现在数据流/生成反馈，"两色分工"守住了。
- **平铺层级贯彻得彻底**：全站实测只有 1 种 `box-shadow` 值，且是透明的 focus 占位——"flat by default" 没有变成"每个卡片都加阴影"。

## 五、布局与空间

### 5.1 三套容器宽度

| 页面 | 容器 | 实际宽度 |
|------|------|---------|
| `/canvas` | `max-w-7xl` | 1280 |
| `/image` | `max-w-[100rem]` | 1440 |
| `/prompts` | 第三套 | — |

三页共用同一个顶栏（`max-w-7xl`，1280，两侧 80px），但页面主体各走各的。顶栏内容边界和页面内容边界对不齐，视觉上"顶栏是浮在上面的一条"。

### 5.2 `/image` 右侧大面积留白

580px 工具面板 + 800px 工作区。空态时工作区中央是一个 384px 的虚线框，其余 400×500 全空。这不必然是错（结果区需要呼吸），但**空态没有任何引导性内容**——没有示例、没有流程提示、没有"三步"分解，只有一句"还没有生成结果"。

### 5.3 圆角有 11 种

实测：`10px`(33) `12px`(17) `9999px`(15) `4px`(10) `8px`(6) `100px`(4) `6px`(3) `16px`(2) `14px`(1) `3px`(1) `2px`(1)

`DESIGN.md` 只声明 12 / 14 / 16 三档。实际主力是 **10px**，而 4px 和 9999px 各有 10 处以上。代码里还有 `rounded-[18px]`(4)、`rounded-[3px]`(2)、`rounded-[2px]`(2)、`rounded-[1px]`(1) 这种一次性值。

## 六、可访问性与触达

### 6.1 [P1] 49 个可点目标小于 44×44

主流尺寸是 **26–28px 高**：

| 元素 | 实测 |
|------|------|
| 平台 chip | 80×27 |
| 场景 chip | 121×27 |
| 「管理」按钮 | 56×26 |
| 区块折叠整行 | 105×27 |
| 主题切换 | 28×28 |
| 复制图标 | 16×16 |

桌面鼠标能点，触屏（面板 406px，`/image` 在 440 下仍是主布局）几乎每次都会点错。这一条在移动端不是"次要问题"。

### 6.2 [P1] 5 个控件没有可读名字

```
<button role="switch" aria-checked="true">        ← 无 aria-label
<button role="switch" aria-checked="false">       ← 无 aria-label
<button class="...h-5...">（色板 16×16）           ← 无文本无 label
<button class="...h-5...">（色板 16×16）           ← 无文本无 label
<a href="/">（Logo，只有 SVG）                     ← 无文本无 label
```

读屏用户听到的是"开关，已选中"和"按钮"，不知道是哪一个。

### 6.3 焦点可见性（部分合格）

14 次真实 Tab 遍历：按钮全部有 2px 靛蓝环（合格），导航链接是 3px 深色环（1.74:1，不合格）。

> 备注：最初用 `element.focus()` 编程式聚焦测得"18/18 无焦点样式"，是误判——`focus()` 不触发 `:focus-visible`。改用真实按键后结论反转，这条记录在此以免误导。

## 七、性能

- **29 / 33 个 `<img>` 没有 `loading="lazy"`**。`/prompts` 是图片墙，首屏 20+ 张缩略图全部立即请求。这是本次唯一值得改的性能项。
- `transition-all` 全站只有 1 处，没有动画化 width/height/top/left 的地方，动效实现是干净的。
- 渐变卡是 CSS 渐变，不是图片，代价可控。

## 九、系统性判断

**这不是"审美不够"，是"系统没被使用"。**

`DESIGN.md` 写得很清楚：四档字号、三种圆角、三档间距、两色分工、平铺层级。实测下来：

- **做到了的**：两色分工、平铺层级、深色对比度基线；
- **没做到的**：四档字号（实际 8 档且主力是 10px）、三种圆角（实际 11 种）、统一页面壳（三页三套）。

原因也很一致：组件层是"就地写一个值"长大的，缺一层把 `text-[11px]` 挡在外面的约束。155 处手写字号、11 种圆角、3 套容器宽度，是同一个病因的三种症状。

**所以修法不是逐个改样式，是先定档位再收敛。**

## 十、建议动作（按顺序）

1. **`/fix-a11y`（手工）** — P1 的 1、2、6 三件事，都是一两行改动，收益最高：选中态文字色、导航焦点环、5 个 aria-label。
2. **`/typeset`** — 重建字号阶（8 → 5 档），确定正文 13–14px、辅助 11px 封底；把 `text-[10px]/[11px]` 从 155 处收敛到 0，改用语义 class（`text-label` / `text-meta` / `text-body`）。
3. **`/arrange`** — 三页统一页面壳：标题档位、对齐方式、容器宽度、首屏节奏。
4. **`/normalize`** — 圆角、间距、字号全部归位到 token；修 `text-primary-foreground` 的失效根因。
5. **`/distill`** — 首屏减负：场景分组、配方默认收起、渐变色卡降噪。
6. **`/colorize`** — 暖色横幅回到冷色体系。
7. **`/polish`** — 收尾。

> 以上可以一次做完，也可以按你指定的顺序来。改完重跑一次审计看分数变化。
